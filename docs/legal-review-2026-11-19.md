## 条文の取り寄せと照合

条文は、e-Gov 法令 API の条の口（`articles`）から、2026-11-19 に取り寄せました。
法令の番号は、research-collaboration の `verification/statutes.json` から取りました。
照合は、互いに独立した次のやり方で行いました。

| やり方 | 結果 |
| --- | --- |
| `node tools/statutes.js`。条の口から取り寄せ直し、記した sha256 と比べる | このリポジトリの条は、どれも記した値と同じ |
| research-collaboration と cpsbvbng26-dotcom が前に取り寄せた同じ条の文と比べる | どの条も、少なくとも一方の写しと一字一句同じ |
| `node verification/check.js`。頁に引いた句が、写した文にそのまま現れるか | すべて現れる |

GitHub の利用規約は、github/site-policy を git で取り寄せ、そのファイルに触れた最後のコミットを履歴から読みました。
引いた句は、そのコミットの文にそのまま現れました。
Anthropic のプライバシーポリシーの句は、この日に頁を取り寄せ直し、同じ句があることを確かめました。
個人情報保護委員会の頁は、作業の環境から届きませんでした。
その句は、Sophaxis の取り寄せの仕事が 2026-11-12 に読んだ記録と、免責事項の引用とで照らしました。

## 見張りの決め

条文と規約の見張りは、水曜に回します。
月曜と火曜と木曜は、ほかのリポジトリの見張りが使っています。
見張りは、cpsbvbng26-dotcom の `verification/statutes.json` の条文と規約も見ます。
その分は、このリポジトリに写し（`verification/canonical-statutes.json`）を持ち、正本の main を読むだけで照らすことにしました。
写しを持つのは、PR で比べる仕事が、その時点の正本に左右されずに同じ結果を出すためです。
正本の main を読むので、正本が変われば、写しとの違いとして見つかります。
ワークフローの鍵はほかのリポジトリに書けないので、違いは、このリポジトリの issue に出します。
写しの条文は、どれも e-Gov 法令 API から取り寄せ直せることを、この日に確かめました。
附則の条は、条の口では取れないので、法令の全文の口（`lawdata`）から、Sophaxis の記録と同じ数え方で取り出します。
GitHub にある規約は、そのファイルに触れた最後のコミットと、引いた句を見ます。
GitHub の外の頁にある規約は、取り寄せ直しません。
作業の環境から届かない頁があり、描かれた頁の文は頁の作りで変わるので、規約が変わっていなくても違いが出るためです。
運営者のほかの創作の場の条文は、見張りません。
Sophaxis の見張りの代わりもしません。

## このリポジトリでは直さない食い違い

次のことは、ほかのリポジトリの文であり、このリポジトリでは直していません。

- research-collaboration の求めの頁は、求めの窓口を様式だけと書き、非公開の答えは、求めた人が GitHub のプロフィールに公開した連絡先へ送ると書いています。連絡先を公開しない人が非公開の答えを受ける道は、その頁にありません。
- 免責事項は、人についての記載でない権利の侵害（著作権・商標など）の知らせの手順を書いていません。
- golden-window-resolution についての求めの手順は、どの頁にも書かれていません。
- 正本の写しの `SECURITY.md` は、非公開の脆弱性報告が有効でないことを 2026-11-12 に確かめたと書いています。このリポジトリは 2026-11-19 に置きました。同じ日に GitHub の API で確かめると、有効ではありませんでした。
- 正本の写しの誤りの知らせの様式は、PyYAML と Ruby の YAML の読み手で読めませんでした。説明の欄の文の中にある、コロンと空白の並びが原因です。GitHub がその様式をどう読むかは、確かめていません。
- golden-window-resolution の誤りの知らせの様式は、突き合わせの受付を書いていますが、そのリポジトリに受付の仕事はありません（同じ点検が見つけたこと）。
- 免責事項の範囲の行は、golden-window-resolution とこのリポジトリを名指していません（同じ点検が見つけたこと）。この入口のリポジトリについての求めは、この入口が自分で決めた手順によります。

## ワークフローと GitHub の追加製品の規約

cpsbvbng26-dotcom の [statutes.json](https://github.com/cpsbvbng26-dotcom/cpsbvbng26-dotcom/blob/main/verification/statutes.json) は、GitHub の追加製品の規約から「If using GitHub-hosted runners, any other activity unrelated to the production, testing, deployment, or publication of the software project associated with the repository where GitHub Actions are used.」を引いています。
このリポジトリのワークフローを、この句に照らして読みました。

| ワークフロー | すること | 読み方 |
| --- | --- | --- |
| `.github/workflows/check.yml` | このリポジトリの頁と様式を検査する | このリポジトリの検査に当たる |
| `.github/workflows/remote.yml` | 頁が指すほかのリポジトリのファイル・節の名・引いた句を、公開の main と照らす | このリポジトリの頁の検査に当たる。読むのは頁が指すファイルだけ |
| `.github/workflows/statutes.yml` | このリポジトリが写して持つ条文と規約を、出どころと照らす | このリポジトリが持つ写しの検査に当たる。週に一度で、取り寄せの間を空けている |
| `.github/workflows/labels.yml` | 様式が使うラベルを作る | このリポジトリの様式を動かすための設定に当たる |
| `.github/workflows/checked-intake.yml` | 正本の写し。誤りの知らせを確かめる | 正本の記録の読み方に従う |
| `.github/workflows/empty-issue.yml` | 正本の写し。本文の空の issue に答える | 正本の記録の読み方に従う |

この読み方は、運営者の読み方です。
GitHub がどう読むかは、確かめていません。

## 結論を出していないところ

次のことは、法令の整理の頁で、結論を出していないと書いています。

- 運営者が個人情報取扱事業者に当たるかどうか。
- issue の様式とメールに書かれたものが、個人情報保護法第21条第2項の書面に当たるかどうか。
- issue の公開が、運営者による第三者への提供に当たらないという扱いが正しいかどうか。
- issue の中身が、個人情報保護法第28条の個人データに当たるかどうか。
- どの事態が、漏えいなどの報告の委員会規則に当たるかどうか。
- 諮問委員への申し出と助言のどの行いが、民法第5条の法律行為に当たるかどうか。
- ある助言の関係を、労働基準法と労働契約法のもとでどう位置づけるか。
